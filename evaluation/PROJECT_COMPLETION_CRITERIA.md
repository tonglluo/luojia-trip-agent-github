# 差旅出行助手：代码与评测阶段完成标准

本文件定义进入 PRD、简历和项目集包装之前必须完成的技术验收项。门槛在正式
评测前确定，避免根据结果临时修改标准。

## 1. 意图识别与编排

- 使用全新、人工复核并冻结的60条 V2 独立测试集。
- 固定同一数据集、模型、Thinking 配置，完成至少3次运行。
- 三次均无 API 或解析错误；如发生平台故障，该次作废并保留故障记录。
- 三次平均意图集合完全匹配率不低于90%。
- 三次平均多标签 Macro F1 不低于95%。
- 三次平均调度优先级完全匹配率不低于95%。
- 三次平均实体字段准确率不低于90%。
- 报告均值、最小值、最大值和逐类 Precision/Recall/F1，不只展示最好的一次。

## 2. RAG

- 建立至少50条人工审核问题，覆盖可回答、跨段信息和不可回答问题。
- 冻结问题、标准来源和关键答案点后再运行。
- 报告 Recall@K、MRR、答案人工评分和不可回答问题处理结果。
- Recall@5 目标不低于90%。
- 人工答案平均分目标不低于1.6/2。
- 不可回答问题不得编造制度内容，正确拒答率目标不低于90%。

如果真实结果未达到目标，应如实报告并完成一次开发集优化；不得修改已经冻结的
测试答案。再次验证必须使用新的独立测试版本。

## 3. 延迟与编排优化

- 串行基线和并行方案使用同一模型、同一任务组合和同一运行环境。
- 每种模式包含预热，并至少完成10次有效重复。
- 报告端到端 P50、P95、平均值和失败率。
- 只有实测结果支持时，才能写“降低 X%”；不预设或虚构50%。
- 并行方案应比串行方案有正向收益，且不能以明显增加失败率为代价。

## 4. 稳定性与产品规则

- 意图识别失败时直接返回服务暂不可用，不错误路由到信息查询。
- 429 限流具备退避重试，并在报告中记录重试次数。
- 同优先级智能体并行执行，Priority 2 能获得 Priority 1 结果。
- 同批记忆读取使用修改前快照，批末统一提交偏好写入。
- 长期记忆、短期对话、Agent 缓存和重启后的记忆持久化均有测试证据。
- 离线核心测试、意图规则测试和评测指标测试全部通过。

## 5. 最终交付物

- 冻结数据集及 SHA-256 清单。
- 意图、RAG、延迟三类原始结果文件。
- 错误归因、优化前后对比和实验限制说明。
- 一份最终技术评测报告，所有简历指标都能追溯到原始结果。
- 一组从新环境可执行的复现命令和面试演示流程。

以上五项全部完成后，本项目的“代码与评测阶段”结束。之后再进入 PRD、产品方案、
简历描述、项目集页面和其他 AI 产品经理项目的补充。
